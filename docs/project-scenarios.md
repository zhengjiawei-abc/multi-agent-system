# QuantumFlow 适用场景

QuantumFlow 更适合做“可视化多 Agent 协作开发工作台”，而不是单纯聊天机器人或单一代码生成器。

## 适合的场景

### 1. 小团队内部开发调度

适合把需求、任务、代码生成、测试、审查、交付放在同一个桌面工作台里。

典型用法：

- 团队负责人录入需求。
- 前端 Agent、后端 Agent、测试 Agent、Reviewer 分工执行。
- 过程通过可视化房间、任务队列和日志展示。

### 2. 需求转代码的演示系统

适合给客户、同事或投资人演示“AI 团队如何从需求生成项目”。

典型用法：

- 输入业务需求。
- 系统拆分职责。
- 生成前端、后端、测试、Review 文档。
- 打包成可下载项目。

### 3. Agent 工作流教学

适合教学多智能体协作、任务路由、代码审查、测试回流和质量门禁。

可展示：

- Agent 分工
- 队列调度
- 失败重试
- 测试反馈
- 审查意见采纳

### 4. 企业内部工具原型

适合快速生成 OA、CRM、工单、图书馆、审批、后台管理等系统原型。

适合特征：

- 有明确业务实体。
- 有列表、搜索、筛选、状态流转。
- 需要前后端和基础测试。
- 更重视快速验证，而不是立即生产上线。

### 5. 开源协作/项目房间原型

适合模拟类似 GitHub 的轻量协作场景。

可用于：

- 项目房间
- 邀请码协作
- Issue 管理
- Agent 审计
- 公开讨论

### 6. Connector/Bot 任务入口

适合把飞书、企业微信、Webhook 等外部消息转成开发任务。

典型用法：

- 外部系统发来需求。
- Connector 归一化消息。
- QuantumFlow 创建任务。
- Agent 执行后回传结果。

## 不太适合的场景

### 1. 强生产级自动上线

目前更适合本地开发、演示、原型和内部测试。

不建议直接用于：

- 自动修改生产数据库。
- 自动发布线上服务。
- 无人工审查的生产变更。

### 2. 高安全合规场景

如果涉及金融、医疗、政务、核心商业秘密，需要额外增加：

- 权限审计
- 密钥托管
- 数据脱敏
- 操作审批
- 私有模型部署

### 3. 超大型代码库全自动重构

当前更适合中小型项目、模块级任务和原型生成。

大型代码库建议先接入：

- 仓库索引
- 精确依赖图
- 增量测试
- PR 级审查
- 沙箱隔离执行

## 命令行启动方式

CMD：

```cmd
qflow desktop
qflow server
qflow platform
qflow admin
qflow status
qflow stop
```

PowerShell：

```powershell
.\qflow.ps1 desktop
.\qflow.ps1 server
.\qflow.ps1 platform
.\qflow.ps1 admin
.\qflow.ps1 status
.\qflow.ps1 stop
```

推荐默认入口：

```cmd
qflow desktop
```

这个命令会启动后端服务，并打开桌面/浏览器工作台。
